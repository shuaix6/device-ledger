# 设备台账管理程序

一个跑在终端里的设备台账工具。查、增、删、改，数据存本地 JSON 文件。

---

## 这是什么

车间里的设备台账原来是 Excel：查一台设备要翻好几页，两台设备重名时容易改错行，删错了没法撤销。

这个程序把台账搬进终端。输入编号就能查、能加、能删、能改，每次改动立刻写回文件，重开程序数据还在。

**给谁用**：管设备的人，或者需要在工位上快速查设备信息的人。

---

## 怎么跑

需要 Python 3.10 以上。

```bash
# 1. 看一眼 Python 版本
python --version

# 2. 进入目录
cd python-learn

# 3. 运行
python v3_devices.py
```

跑起来会看到菜单：

```
==== 设备台账 ====
1. 查看全部设备
2. 按名称查
3. 按车间查
4. 新增设备
5. 删除设备
6. 修改功率
0. 退出
请选择：
```

---

## 能做什么

| 编号 | 功能 | 说明 |
|---|---|---|
| 1 | 查看全部 | 每台一行，末行显示总数 |
| 2 | 按名称查 | 输入「机床」能查出「数控机床」（模糊匹配） |
| 3 | 按车间查 | 输入「2号车间」只显示这个车间的设备 |
| 4 | 新增设备 | 自动分配新 id，**同名同型号不许重复添加** |
| 5 | 删除设备 | 先显示这台设备，输入 `y` 才真删 |
| 6 | 修改功率 | 按 id 找到设备，改功率并写回文件 |
| 0 | 退出 | — |

**所有改动实时写回 `devices.json`**，不需要手动保存。

---

## 数据长什么样

`devices.json` 是一个数组，每台设备是一个对象：

```json
[
  {
    "id": 1,
    "name": "数控机床",
    "model": "CNC-850",
    "power": 15.5,
    "location": "3号车间"
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 整数 | 程序内部编号，自动分配，不重复 |
| `name` | 文字 | 设备名称，可以重名 |
| `model` | 文字 | 设备型号 |
| `power` | 小数 | 功率，单位 kW |
| `location` | 文字 | 所在车间 |

`id` 用「当前最大 id + 1」分配，**不用「数量 + 1」**——因为删过设备之后数量会变小，会撞号。

## 已知限制

**功能上**

- 只有终端界面，没有图形窗口
- 不支持批量导入导出（Excel / CSV）
- 没有登录和权限控制，谁打开都能改

**技术上**

- 数据存在单个 JSON 文件里，设备上千台之后每次读写都会变慢（现在几十台没问题）
- 不支持多人同时操作，两个人同时改会互相覆盖
- 没有自动备份，改坏了要靠 git 历史或手动备份恢复

## 代码结构

拆成了 10 个函数，主流程（`main`）只有 20 行：

```
load_devices()      读文件
save_devices()      写文件
print_one()         打印一行设备信息
show_all()          查看全部
find_by_name()      按名称查
find_by_location()  按车间查
add_device()        新增
delete_device()     删除
edit_power()        改功率
main()              菜单循环 + 分发
```

**为什么拆**：拆之前 155 行全写在 `while True` 里，一个分支 30 行；改一处功能要在一堆代码里找位置。拆完之后每个函数只做一件事，改哪块就动哪个函数。

## 从需求到代码的顺序

这个项目是按「先定规格，再写代码」做的：

1. 写 `v3_需求.md`——8 条功能、字段定义、明确不做哪三件事
2. 设计数据结构——`id` 为什么是整数、`power` 为什么是小数
3. 写代码，每完成一块就用用例验一遍
4. 重构、复测，确认结构改了功能没坏

**第 1 步花的时间，在第 3 步省回来了。** 做到一半想加功能时，翻回去看「明确不做的」那三条，就知道该不该加。
